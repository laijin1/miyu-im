# 🔐 发布签名密钥备份与说明（务必阅读）

## 一、这两个文件是什么

| 文件 | 作用 | 能不能丢 |
|---|---|---|
| `release.jks` | 正式发布签名密钥库 | **绝对不能丢** |
| `keystore.properties` | 里面是上面这个密钥库的密码 | **绝对不能丢** |

两者都已被 `.gitignore` 忽略，**不会进 git**，也不会随仓库分发——这是有意的，
因为它们一旦泄露，别人就能签出和你一模一样、可以覆盖安装你 App 的假更新包。

因此**它们现在只存在于你这台电脑上**。请立刻做异地备份。

## 二、立刻要做的备份（照做）

把下面两个文件复制到**至少两个**不同的地方：

```
miyu-app\release\release.jks
miyu-app\release\keystore.properties
```

建议位置（任选两个以上）：

- U 盘 / 移动硬盘
- 你自己的网盘私有目录（不要放公开分享链接）
- 密码管理器（1Password / Bitwarden 的安全笔记）
- 打印出来锁抽屉（最土但最保险，密码就在那个 properties 文件里）

> 把这个目录整体压缩加密后备份也可以：
> ```powershell
> Compress-Archive -Path "<本地路径>\miyu-app\release\release.jks","<本地路径>\miyu-app\release\keystore.properties" -DestinationPath "<本地路径>\密语签名密钥备份.zip"
> ```
> 然后**给这个 zip 设一个密码或放进加密盘**，再复制到别处。
>
> 📌 工程已于 2026-09 从 `<本地路径>` 迁到 **`<本地路径>`**（纯 ASCII 路径）。
> 若你在旧路径看到这份文档，请以新路径为准。

## 三、丢了会怎样

Android 只允许**同一签名的包**覆盖安装。所以：

- 密钥/密码丢了 → 你再也无法给已安装的用户推送新版本
- 想发新版只能**换包名**（等于做一个新 App），老用户数据、好友关系、聊天记录全部无法延续

没有任何办法找回，没有"官方申诉"能解决。**现在就备份。**

## 四、密钥信息（便于日后核对）

```
密钥库文件 : release.jks
别名       : miyu
算法       : RSA 2048
有效期至   : 2056-09-03
证书 SHA-1 : 0EF663B814E9B48D75086935D698D90C37A030FD
证书 SHA-256: C60ACE246E5985F61D9A9CE0D90BEC7009392169843134C6B4BCFC456FEC4FD5
```

核对这些值是否与 `release.jks` 一致（会提示输入密码，直接粘贴 properties 文件里的那个）：

```powershell
keytool -list -v -keystore release.jks -storetype PKCS12 -alias miyu
```

## 五、换电脑 / 重装系统后怎么发版

1. 把 `release.jks` 和 `keystore.properties` 放回 `miyu-app\release\` 目录
2. 正常执行 `scripts\release-commit.bat` 即可

`build.gradle` 会自动从 `keystore.properties` 读取路径与密码，**不需要**在代码里写任何密码。

## 六、这次换签名对老用户的影响（重要）

修复前发布的包里，APK 用的是 **Android 调试证书**签名（全世界公开的固定密钥）。
本次修复换成了上面这个正式密钥，因此：

- ⚠️ **已装旧版的手机，无法直接覆盖升级**，会提示"应用未安装/签名不一致"
- 需要**卸载旧版再装新版**（一次性）。聊天记录在服务端，卸载重装后登录即可恢复
- 新版 App 内的"检查更新"已经加了签名校验，同时把旧调试证书加入允许列表，
  所以老用户**能正常下载**新包，只是最后一步安装仍需先卸载旧版

发版时请提前告知家人/用户这一步。

## 七、日常维护红线

- ❌ 不要在 QQ/微信里直接传这两个文件
- ❌ 不要把密码写进 `build.gradle`、代码注释或 README
- ✅ 换密码/换密钥前先想清楚：换了就等于新 App，老用户升级链断裂
