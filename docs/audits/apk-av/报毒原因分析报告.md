# `miyu.apk` 被判定为"危险捆绑软件"的原因分析

分析对象：`<本地路径>`
SHA-256：`58AE962637B050A92E11E8E8407B9D6C70BE6566A7CB0630BD2F3C6475CCE239`
包名 `com.familychat.app`，versionCode 120 / versionName 1.0.120，目标 SDK 34

---

## 一、结论（一句话）

**它不是真的被"捆绑"了第三方软件，而是"用调试版（debug）签名 + 自带下载并安装 APK 的自动更新功能"这两个特征叠加，命中了安全软件判定"捆绑/流氓推广"的通用规则。**

其中**调试版签名**是决定性因素——它同时构成了 `android:debuggable=true` 和"公开的 Android 调试证书"，几乎必然触发报毒。

---

## 二、决定性证据

### 1. 对外发布的 APK 就是调试版（debug）APK，而且是同一个文件

三个文件的 SHA-256 完全相同：

| 文件 | 路径 | SHA-256 |
|---|---|---|
| 待检测包 | `_apkcheck\miyu.apk` | `58AE9626...CCE239` |
| 对外发布包 | `miyu-app\release\密语.apk` | `58AE9626...CCE239` |
| **构建产物** | `apk\FamilyChatApp\app\build\outputs\apk\debug\app-debug.apk` | `58AE9626...CCE239` |

发布包与 `assembleDebug` 的产物**逐字节一致**，即"发布版 = 调试版"。

根因在构建配置里：`apk/FamilyChatApp/app/build.gradle` 只定义了 `release` 构建类型，
**整个工程没有配置任何 `signingConfig`**（未定义 keystore、keyAlias）。因此
`gradlew assembleRelease` 产出的是 `app-release-unsigned.apk`（无法安装），
实际只能用 `assembleDebug` 出货 —— 而 `build-apk.bat` 里写的正是 `call gradlew.bat assembleDebug`。

### 2. 签名证书是"人人都有"的 Android 调试证书

```
Signer #1 certificate DN: C=US, O=Android, CN=Android Debug
SHA-1   : 96:90:47:5C:12:AB:3B:E6:AE:2B:E3:05:31:BE:BB:87:06:42:A6:4C
SHA-256 : 60674BA9656D5B2B78DF5B9439C07BDFC6106AE76760900B77A67AF0A10BBE14
```

本机 `~/.android/debug.keystore` 的 SHA1 完全一致（`96:90:47:...:A6:4C`）。

调试证书的私钥是全世界公开的固定值。任何安全软件、应用商店、风控系统看到
**"发布包用调试证书签名"**，都会判定为"非正规发行渠道 / 可被任意第三方重新打包"，这是
"捆绑软件"类目最典型的触发条件。

### 3. 应用被标记为可调试

`aapt dump xmltree` 中 `application` 节点存在：

```
android:debuggable = 0xffffffff   (= true)
```

`debuggable=true` 会额外命中"应用可被调试/可被注入"的风险规则。

### 4. 具备"下载并安装 APK"的能力（这是"捆绑"字面上的直接来源）

清单中声明：

```
android.permission.REQUEST_INSTALL_PACKAGES     ← 允许安装其他应用
android.permission.REQUEST_IGNORE_BATTERY_OPTIMIZATIONS
android.permission.FOREGROUND_SERVICE / FOREGROUND_SERVICE_DATA_SYNC
```

并且 `UpdateActivity.java` 确实实现了完整链路（这是功能，不是恶意）：

```
GET <server>/version.json   → 取 versionCode / downloadUrl / apkSha256
GET <downloadUrl>           → 下载新 APK（三方回退：公共下载目录 → PackageInstaller 会话 → FileProvider）
校验 SHA-256 一致 + 读 APK 真实 versionCode 一致
调起系统安装界面
```

即应用会**自己下载一个 APK 并引导用户安装**。主流安全软件的启发式规则对
"应用内下载 APK + REQUEST_INSTALL_PACKAGES"的组合一律给"捆绑安装/推广"标签，
不管它下载的是不是自己的新版本。

## 三、加重判定的次要因素

| # | 因素 | 证据 | 影响 |
|---|---|---|---|
| 1 | **允许明文 HTTP 流量** | `res/xml/network_security_config.xml` 里 `cleartextTrafficPermitted="true"` | 下载的更新包走明文 HTTP（局域网地址）时，可被中间人替换；安全软件视为高危 |
| 2 | **仅 v2 签名，无 v1/v3** | apksigner：v2=true，v1/v3/v4=false | 签名方案单薄，且调试证书 + 无时间戳 |
| 3 | **请求忽略电池优化** | `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 常被杀软归为"常驻后台/保活"行为 |
| 4 | **同一 APK 多个文件名分发** | `密语.apk`、`miyu.apk`、`知网.apk`，下载页还有 `/apk` 固定地址 | 同 Hash 多名称、非应用商店直链分发，易被判定为"渠道包/改包" |
| 5 | **12 个 DEX + 53 MB** | classes.dex ~ classes12.dex | 体积与 DEX 数量本身会触发启发式扫描的注意（实际来自 AndroidX/Material/OkHttp/Glide/Media3/WebRTC 等库） |
| 6 | **敏感权限齐全** | CAMERA、RECORD_AUDIO、READ_MEDIA_IMAGES、FOREGROUND_SERVICE | 与"能装应用"的能力叠加后风险评分上升 |

## 四、同时可以确认：包内**没有**真正的捆绑软件

对包内容做了逐项核查，未发现任何第三方推广/广告/统计 SDK 或被塞入的外部程序：

- **APK 目录结构**：只有 `classes*.dex`、`res`、`resources.arsc`、`lib`（4 个 ABI 的
  `libjingle_peerconnection_so.so`，即 WebRTC）、`META-INF`、`kotlin`、`okhttp3`、`pinyindb`。
  **没有** `assets/`、**没有**内嵌的任何 `.apk` / `.jar` / `.exe` / `.so`（除 WebRTC）。
- **DEX 特征串扫描**：`umeng`、`com.qq.e`(优量汇)、`bytedance`/`pangle`、`kuaishou`、
  `applovin`、`adcolony`、`unity3d`、`appsflyer`、`bugly`、`getui`、`jpush`、`sensorsdata`、
  `talkingdata`、`gdt` 等主流广告/统计/推送 SDK 包名 —— **全部 0 命中**。
- **危险 API 特征**（`DexClassLoader`、`Runtime.exec`、`ProcessBuilder`、`su`、`BusyBox`、
  `SmsManager.sendTextMessage` 调用等）—— **全部 0 命中**。
  （扫描中出现的 `TelephonyManager`、`AccessibilityService`、`mount`、`getDeviceId` 等字样，
  是 Android 框架/AndroidX 库自身的字符串常量，非本应用代码调用。）
- **依赖清单**（`app/build.gradle`）全部为公开正规库：AndroidX、Material、
  OkHttp、Gson、Glide、uCrop、ZXing、Stream WebRTC、security-crypto、Media3、pinyin4j。
- **更新链路本身还做了防护**：同源校验（拒绝外部下载地址）、SHA-256 完整性校验、
  下载包真实版本号核对、失败即删除不自动重试。

**所以：报毒是"发行方式"问题，不是"包里塞了东西"问题。**

## 五、修复建议（按优先级）

### P0 —— 直接消除报毒

1. **生成正式发布签名并签名出货**（这是最关键的一步）

   ```bash
   keytool -genkeypair -v -keystore release.jks -alias miyu \
     -keyalg RSA -keysize 2048 -validity 10000
   ```

   在 `app/build.gradle` 的 `android { }` 中补上：

   ```groovy
   signingConfigs {
       release {
           storeFile file("../../release/release.jks")
           storePassword System.getenv("MIYU_STORE_PASS")
           keyAlias "miyu"
           keyPassword System.getenv("MIYU_KEY_PASS")
       }
   }
   buildTypes {
       release {
           minifyEnabled true
           signingConfig signingConfigs.release      // ← 补上这行
           proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
       }
   }
   ```

   然后 **`gradlew assembleRelease` 出货**，把 `build-apk.bat` 和 `scripts/release-commit.bat`
   里的 `assembleDebug` / `app-debug.apk` 全部改成 `assembleRelease` / `app-release.apk`。

   > ⚠️ 换签名后 `applicationId` 不变但签名变了，老用户**无法覆盖安装**，必须卸载重装一次
   > （或在首次发布正式包时就定下来）。keystore 必须妥善备份，丢失后无法再更新。
   > 注意 `release` 已开启 `minifyEnabled true`，先跑一遍完整功能回归（WebRTC、扫码、支付回调易被混淆破坏）。

2. **确认 `debuggable` 随正式包消失**：`aapt dump xmltree` 应不再出现
   `android:debuggable`。同时建议显式加 `android:debuggable="false"` 兜底。

3. **补全签名方案**：在 `build.gradle` 中启用 v1+v2+v3（默认已含 v2/v3，但 v1 需
   `enableV1Signing true`，兼容旧机型）。

### P1 —— 降低启发式评分

4. **把更新下载改为 HTTPS**。局域网自签场景不要在全局放开明文：
   将 `network_security_config.xml` 改为默认禁止明文，仅对局域网服务器 IP 加
   `domain-config cleartextTrafficPermitted="true"` 白名单；公网/隧道场景（
   `.cloudflare-tunnel/familychat.yml` 已配 `download.your-domain.com`）必须走 HTTPS。
5. **更新包做签名比对**：下载后除 SHA-256 外，再用 `PackageManager.getPackageArchiveInfo`
   配合 `GET_SIGNING_CERTIFICATES` 校验新包签名与当前应用一致，防止被替换。
6. **去除不必要的权限/行为**：`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 若非必需建议去掉；
   保活改用前台服务通知（已声明 `FOREGROUND_SERVICE_DATA_SYNC`，符合规范即可）。
7. **统一分发标识**：避免同一 APK 用 `密语.apk` / `miyu.apk` / `知网.apk` 多名字分发，
   固定一个文件名与一个下载地址。

### P2 —— 主动解除误报

8. 拿正式签名包去 **VirusTotal** 复检；若仍有个别厂商报毒，通过各厂商
   （腾讯、360、华为、小米等）的**误报申诉通道**提交白名单申请，附上本报告与包特征。
9. 长远看：上架正规应用商店（或做应用签名备案）是从根上避免"未知来源 + 自动装包"
   被标记的办法。

## 六、复现命令（自查用）

```powershell
# 签名证书（关键证据）
apksigner.bat verify --print-certs --verbose miyu.apk

# 是否可调试 / 权限清单
aapt.exe dump xmltree  miyu.apk AndroidManifest.xml
aapt.exe dump permissions miyu.apk

# 确认发布包 == 调试包
Get-FileHash miyu.apk, app-debug.apk, 密语.apk -Algorithm SHA256
```

> 注意：`aapt` 无法处理含中文的路径（会报 `Illegal byte sequence`），
> 请先把 APK 复制到纯英文路径再执行上述命令。
